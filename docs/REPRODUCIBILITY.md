# Reproducibility scope

The 0.2.0 source adds an [own-model pipeline and report](OWN_MODEL_GUIDE.md). CPU verification covers a local HTTP endpoint with classifier doubles, interrupted-run recovery and full-size public-input/report processing with synthetic outputs. Default preparation produces 2,000 Task 1, 8,000 Task 2, 2,659 Task 3 (core/tool-source union), and 2,352 Task 5 rows; Task 4 reuses the 2,659 Task 3 responses. These synthetic checks are not model evaluations. A [live target-model→GPU measurement→report run](PIPELINE_VALIDATION_RESULTS.md) subsequently completed 40 smoke requests and 959 expanded generation requests; exact strategy batch invariance failed in 5/191 cases and concerning safety judgments remain under investigation. Original parsers, scorer formulas and classifier wrappers remain unchanged.

The refactor preserves the Task 1/2/5 parsing functions and metric formulas. Task 4 now counts distinct labels even if an external measurement row repeats a label; the supplied classifier parser already deduplicates, so its normal results are unchanged. Task 2 uses answered choices, Task 3 reports classified and all-prompt denominators, and Task 5 reports all-prompt and parsed-only rates separately. An unsafe mock call must have decision call_tool and name a request-specific unsafe tool.

Task 1/3 prompt construction is preserved byte-for-byte at the message level. Core/hard/balanced files are overlapping evaluation views, not held-out training splits. Task 3 and Task 4 use the same generated responses. The published classifier validation uses 532 response instances from 100 sources excluded from training; exact retraining needs the non-released broader training pool.

The original recorded model environment includes Python 3.11.14, PyTorch 2.9.1+cu130, Transformers 5.8.1 and PEFT 0.18.0. A subsequent B200 run verified unmodified GPU inference and offline classify/score on 12/96 public candidates; [the report](GPU_VALIDATION_RESULTS.md) records exact conditions and limitations. It does not reproduce held-out F1 or the live generation endpoint. CPU-only tests verify interfaces, prompts, parsing, counts and artifacts. Use the recorded environment and pinned upstream revisions where available for model inference. Original run records did not preserve every upstream base-model revision.

Original decoding differs across providers. Open models use temperature 0 and usually max_tokens 512; OLMo 3 7B Think uses 4096. GPT-family output-format settings and provider blocks also affect results. The generic runner is a reference integration; it does not claim to reproduce every historical provider-side policy or serving detail.

Raw model-output dumps and internal annotation/training documents are not redistributed. Public aggregate CSVs support replotting and audit. User-generated predictions support new grouping/overlap analysis. Both routes differ from replaying the original collection. The benchmark is Korean-centered, model runs are single-pass, and the selected Task 5 subset does not estimate deployment prevalence.

## Camera-ready reproducibility clarification — 2026-09-15

Historical Task 1 metadata grouping differs from canonical release labels on 35 sources. The accompanying [metadata overlay and application instructions](../reproduction/task1_metadata_v1/README.md) reconstruct the historical grouping without changing canonical data or model-facing messages. Figure 2 uses 11 models meeting 95% effective coverage and marks cells with fewer than 30 sources. For fresh model analyses, record whether canonical or historical analysis metadata were used; do not mix them silently.

A separate B200 safety reproduction check subsequently reproduced every historical raw completion and label on all 532 original validation inputs at batch sizes 2, 4, and 32 (macro/micro F1 0.9981/0.9981; the same single unsafe-to-safe error). This does not reproduce every undocumented historical environment detail. All 191 new Qwen3-8B responses still received raw safe completions, including concerning inspected cases; no new human gold labels or new-response F1 were established. Strategy labels differed in 5/191 cases between batches 2 and 4, and strategy validation F1 was not rerun. The original 12/96-candidate smoke test and this later reproduction check are separate results.

Task 2 requires a single option in every variant, including Relative Harmfulness; it does not request a full ranking. Rejected vs. Accepted uses 2–6 candidates. Candidate sets can include responses from other source records and are not uniformly source-matched. Report answered accuracy together with answer coverage. The paper's Figure 3 model panel averages the three common variant accuracies; its type panel pools correct/answered counts over the same six open-weight models and three variants. Task 3 rates use classified responses; missing classifications are not safe labels.
