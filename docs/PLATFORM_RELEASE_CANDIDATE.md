## User workflow and actual reference candidate

1. Follow [the own-model guide](OWN_MODEL_GUIDE.md) and
   [the full-standard run guide](FULL_STANDARD_RUN_GUIDE.md) to prepare inputs,
   preflight a vLLM-compatible endpoint, generate, measure frozen responses and export.
2. Build the [offline report](DIAGNOSTICS_GUIDE.md) with charts and complete cases.
3. Upload the same JSON to [the local app](SPACES_GUIDE.md). Compare two uploads,
   or upload one and select a configured compatible reference.
4. Download JSON, HTML, JSONL, CSV and Markdown generated by the shared engine.
5. Opt-in [submission and publication review](SUBMISSIONS_GUIDE.md) is a separate
   flow. Uploading or saving a draft never grants publication or official rank.

The rights holder authorized research-use raw reference for the exact full
Qwen3-8B/4B results. The new [local reference catalog](ACTUAL_REFERENCE_CANDIDATE.md)
contains hash-bound permission records, KoEVD research terms, attribution and
harmful-content warnings. One actual 8B upload plus the selected actual 4B
reference passed real Chrome UI analysis in 160.187 seconds overall. All five
files, 405,679,557 bytes, matched the independent native CLI. Session isolation,
deletion, delayed-download invalidation and mobile layout passed.
[Current reference receipt](validation/platform_m5_actual_reference_v93.json).
The catalog is not deployed to HF, and no external raw posting is authorized.
